Overview

D. manager is the working surface for Drosophila lab stock operations. It keeps stocks, crosses, trays, flip timing, labels, and workbook-based administration in one application so the physical bench workflow stays synchronized with the record system.

Use It For

  • tracking active stocks and active crosses
  • organizing tray layouts and occupied positions
  • recording flips with status and comments
  • printing QR-backed labels
  • exporting and importing workbooks as admin

Main Navigation

  • Home for the dashboard and attention queue
  • Flipper for rapid maintenance entry
  • Schedule for upcoming daily work
  • Stocks, Crosses, and Trays for record maintenance
  • Tools for user guide, logout, and admin-only controls

Deployment-Ready Setup

Use this checklist after the application is deployed and reachable. It is written to help an admin turn a running instance into a lab-ready system.

  1. Confirm that login, registration, and the main shell load without layout or session issues.
  2. Create or bootstrap an administrator account.
  3. Open Application Settings as admin and fill in lab name, administrator name, and administrator email.
  4. Create tray definitions that match the physical trays used in the lab.
  5. Decide whether to import a workbook or start with manual stock and cross entry.
  6. Assign recovery emails to users who need password reset support.
  7. Configure SMTP if reminder emails and reset emails should be delivered.
  8. Verify that exactly one running app instance has the scheduler enabled.
  9. Run a workbook export and keep it as the first known-good snapshot.
Scheduler rule The reminder scheduler is intended to run on a single active app instance. Do not enable it on multiple live instances unless the coordination model is changed.
Health checks Production deployments expose /health and /health/ready. Use them during rollout and after upgrades.

Access And Accounts

The app uses username and password authentication. Operators work inside their own data scope, while administrative controls remain restricted to the admin account.

Login

  • Enter a username and password on the login form.
  • Successful login refreshes user state and returns you to Home.
  • Sessions are permanent and rotation is handled when auth state changes.

Registration And Reset

  • Registration is available from the login page.
  • Recovery email is optional at registration time but strongly recommended.
  • Password reset uses a recovery email link when mail delivery is configured.
Important correction Password reset does not use a shared master password. It depends on the user having a recovery email and the deployment having working outbound mail.

Daily Operating Loop

Most operators can think about the app in one repeatable sequence: review the queue, do physical maintenance, record flips, then clean up placements and labels.

  1. Open Home and review overdue items, due-today items, and queue suggestions.
  2. Open Schedule to see which days and trays will drive the next bench session.
  3. Use Flipper while doing the actual vial work.
  4. Use Stocks, Crosses, and Trays to update the record side after the bench work is complete.
  5. Generate labels before returning new or relabeled vials to storage.

How Attention Works

Home treats these as high-attention states:

  • items due today
  • items overdue
  • items marked Showing Issues
  • items marked Needs refresh

Archived records with No longer maintained are removed from the standard active views unless you explicitly filter for them.

Stocks

Stock Explorer is the primary working list for fly lines.

Explorer Capabilities

  • filter by type, tray, status, food type, provenance, and species
  • fuzzy search across IDs, genotype text, name, location, and comments
  • bulk selection for labels, flip, status change, and tray removal
  • default exclusion of archived records

Creating A Stock

  • enter manually
  • prefill from an internal stock to carry forward line details
  • prefill from Bloomington data when a valid stock identifier is available

Recommended Fields To Review

Source ID
External reference such as a Bloomington stock number.
Genotype
The core genetic description used for search, labeling, and planning.
Tray placement
Only set once the physical vial has a confirmed position.
Maintenance values
Vial lifetime, flip frequency, and developmental time drive scheduling behavior.
Archiving vs deletion Mark a line No longer maintained when you want to stop active maintenance while preserving history. Permanent deletion is meant to happen only after archival.

Crosses

Cross management parallels stock management but starts from existing parent stocks and predicted offspring information.

Cross Explorer

  • filter by male species, female species, tray, status, and food type
  • search across name, tray data, and comments
  • run the same bulk workflows used in stock explorer

Create A Cross

  • choose male and female parent stocks
  • set maintenance values and optional tray placement
  • review the predicted offspring genotype before saving
  • use scanner-assisted parent lookup when supported hardware is available
Do not assume unavailable features The current app supports cross creation, maintenance, labeling, and exploration. It does not expose a dedicated in-app "convert this cross into a stock" workflow in the current route set.

Trays

Tray records represent real physical storage surfaces. Use them to keep bench reality and application reality aligned.

Tray Setup

  • define a unique tray ID
  • name the tray in a way operators recognize immediately
  • set the row and column count to match the physical layout
  • add a short description when a tray has a special role

Tray Occupancy

  • occupied positions show live items
  • blocked positions show space reserved by multi-vial requirements
  • empty positions are available for placement

Moving Items

  • place a stock or cross into a tray position
  • move the item when its physical home changes
  • remove the item from tray placement if it no longer has a fixed location
Why placement can fail A placement can be rejected because the target is occupied, blocked, too small for the required vial footprint, or because the item is already archived.

Flipper And Schedule

The Flipper is the fastest path for recording maintenance, while Schedule is the planning surface for the next work block.

Flipper

  • accepts manual UID entry
  • supports scanner-driven lookup
  • records status changes and comments during the flip
  • prevents accidental rapid re-flips using last-flip checks

Schedule

  • groups work by day
  • lists items due for that day
  • shows trays needed for the work block when available
  • can generate labels for a specific scheduled day

Status Reference

  • Healthy for lines that are in normal shape
  • Showing Issues for lines that need closer review
  • Needs refresh for lines that need immediate intervention
  • Ordered for lines tracked before they are fully active
  • No longer maintained for archived lines
Email reminders Reminder delivery is optional. If SMTP is configured and a user has an email on file, the scheduler can send daily flip reminders. If mail is not configured, the scheduler skips delivery cleanly.

Labels And Scanners

Label generation and scanner input are designed to reduce transcription work during repetitive maintenance sessions.

Where Labels Come From

  • selected items in Stock Explorer
  • selected items in Cross Explorer
  • a single scheduled day in Schedule

Scanner Flow

  1. connect the scanner
  2. choose the available port in the scanner-enabled screen
  3. start scanning
  4. scan the QR code
  5. review the resolved record and complete the action
Blank spaces Label generation supports adding blank spaces so partially used sheets can still be aligned correctly during printing.

Workbooks

Workbook import and export are administrative workflows. Treat them as controlled data operations, not routine operator actions.

Export

  • download a current workbook snapshot
  • use the export as the safest template for future imports
  • capture a structured checkpoint before large admin changes

Import

  • upload only .xlsx files
  • start from a fresh export whenever possible
  • validate sheet structure and IDs before upload
  • run imports in a controlled admin session
Import caution Import changes data in bulk. Export first, keep the source workbook, and do not treat import as an undo-friendly action.

Admin Operations

Administrative tools live under the Tools menu and settings page.

Theme Settings
Set dark mode preference and the interface accent color.
Lab Information
Control the displayed lab name, administrator name, and administrator email.
Bloomington Update
Run a manual stock-data refresh that also updates gene metadata.
Gene Metadata Only
Refresh gene collections using existing Bloomington data without a full stock-data download.
Operational recommendation Before a major data refresh, run a workbook export and confirm the backup policy from the deployment runbooks is active.

Go-Live Checks

  1. Login works for at least one operator and one admin.
  2. Home renders live metrics without missing tray or queue data.
  3. One stock, one cross, and one tray can be created successfully.
  4. Flipper accepts manual UID entry.
  5. Schedule renders upcoming items.
  6. Label generation produces a PDF.
  7. Admin export succeeds.
  8. Backup and restore ownership is clear before launch.

Troubleshooting

A UID Does Not Resolve

  • confirm the item belongs to the logged-in user
  • confirm the scanned or typed UID matches the saved record
  • confirm the item was not permanently deleted

Reset Emails Never Arrive

  • confirm the user has a recovery email
  • confirm SMTP is configured
  • confirm the deployment can actually send outbound mail

Reminder Emails Never Arrive

  • confirm the scheduler is enabled on exactly one instance
  • confirm SMTP is configured
  • confirm the user has an email on file

Tray Placement Fails

  • the target may already be occupied
  • the target may be blocked by a multi-vial footprint
  • the item may need more contiguous space than is available
  • the item may already be archived
